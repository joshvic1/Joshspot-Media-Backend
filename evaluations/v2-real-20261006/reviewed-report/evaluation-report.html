Repeated questions and supported questions

The problem is not only keyword recognition. For example, “Second” can be interpreted as management, then rejected during state merge because its platform/item is unresolved. The planner sees no accepted service and asks the same service question again. Other cases assume a platform instead of asking it. Valid questions about performance and requirements often reach retrieval/planning but fall into validation handoff. Rejected intermediate prose is not saved, so some composition-versus-validator fault attribution remains uncertain.

Each repetition record includes prior state, model interpretation, accepted/rejected state changes, retrieval, planner output and state afterward. This distinguishes failure to understand from failure to store and failure to act. See all repetition evidence and detected/answered/deferred/missed customer requests.
